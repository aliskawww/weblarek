# Проектная работа «Web-ларёк»

Стек: **HTML**, **SCSS**, **TypeScript**, **Vite**

«Web-ларёк» — одностраничный интернет‑магазин с каталогом товаров, корзиной и оформлением заказа в два шага. Интерфейс построен на модальных окнах, логика приложения реализована по паттерну **MVP (Model‑View‑Presenter)** и событийной модели.

---

## Установка и запуск

```bash
npm install
npm run dev
```

Сборка:

```bash
npm run build
```

---

## Структура проекта

- `index.html` — разметка страницы и HTML-`<template>` для компонентов.
- `src/main.ts` — слой **Presenter**: связывает модели и представления, подписывается на события, вызывает методы моделей и рендерит View.
- `src/types/index.ts` — единый файл типизации проекта.
- `src/utils/constants.ts` — константы (`API_URL`, `CDN_URL`, `categoryMap` и др.).
- `src/utils/app-events.ts` — единый список событий приложения.
- `src/utils/utils.ts` — DOM-утилиты (`ensureElement`, `cloneTemplate` и др.).
- `src/components/base/` — базовые классы инфраструктуры:
  - `Api` — базовый HTTP‑клиент.
  - `Component` — базовый класс представлений.
  - `Events` — брокер событий `EventEmitter`.
- `src/components/` — код предметной области:
  - `LarekApi` — API‑клиент приложения.
  - `models/` — слой Model.
  - `view/` — слой View.
- `src/scss/styles.scss` — входной файл стилей.

---

## Архитектура

Приложение разделено на 3 слоя:

- **Model** — хранит состояние приложения, изменяет данные и эмитит события.
- **View** — отвечает за отображение интерфейса и пользовательские действия, не содержит бизнес‑логики.
- **Presenter** — связывает Model и View через подписки на события, реализует пользовательские сценарии.

Связь между слоями построена через `EventEmitter`.

## Основные сущности и типы

Проект использует типы из `src/types/index.ts`.

### Основные типы
- `IProduct` — товар каталога.
- `IProductsResponse` — ответ API со списком товаров.
- `PaymentMethod = 'card' | 'cash'` — способ оплаты.
- `IApiOrder` — данные заказа для отправки на сервер.
- `IApiOrderResult` — результат успешного оформления заказа.
- `ValidationErrors` — объект ошибок валидации.

Особенность модели товара:
- `price: number | null`
- если `price === null`, товар отображается как недоступный для покупки, но доступен для предпросмотра.

## События приложения

Файл: `src/utils/app-events.ts`

### События моделей
- `catalog:changed` — изменился каталог товаров.
- `preview:changed` — изменился выбранный товар для предпросмотра.
- `basket:changed` — изменилось содержимое корзины.
- `buyer:changed` — изменились данные покупателя.

### События представлений
- `product:open` — пользователь открыл карточку товара из каталога.
- `card:action` — действие с товаром в превью:
  - если товар уже в корзине — удалить,
  - если товара нет в корзине — добавить.
- `basket:open` — открыть корзину.
- `basket:item-remove` — удалить товар из корзины.
- `basket:checkout` — перейти к оформлению заказа.
- `form:changed` — пользователь изменил поле формы.
- `order:next` — переход ко второму шагу оформления.
- `order:pay` — подтверждение и отправка заказа.
- `success:close` — закрыть окно успешного оформления.
- `modal:close` — запрос на закрытие модального окна.

## Инфраструктура

### `Api`
Файл: `src/components/base/Api.ts`

Базовый HTTP‑клиент.

**Основные методы:**
- `get<T>(uri: string): Promise<T>`
- `post<T>(uri: string, data: object, method?: ApiPostMethods): Promise<T>`

### `EventEmitter`
Файл: `src/components/base/Events.ts`

Брокер событий приложения.

**Основные методы:**
- `on(event, callback)`
- `emit(event, data?)`
- `trigger(event, context?)`

### `Component<T>`
Файл: `src/components/base/Component.ts`

Базовый класс представлений.

**Основной метод:**
- `render(data?: Partial<T>): HTMLElement`

Метод `render` обновляет свойства экземпляра через `Object.assign`, что позволяет использовать сеттеры в дочерних компонентах.

## Модели данных

### `ProductsModel`
Файл: `src/components/models/ProductsModel.ts`

Хранит каталог товаров и товар, выбранный для предпросмотра.

**Ответственность:**
- сохранить список товаров,
- вернуть список товаров,
- найти товар по `id`,
- сохранить выбранный товар для предпросмотра.

**Основные методы:**
- `setItems(items: IProduct[]): void`
- `getItems(): IProduct[]`
- `getProductById(id: string): IProduct | undefined`
- `setPreview(id: string): void`
- `getPreview(): IProduct | null`

### `CartModel`
Файл: `src/components/models/CartModel.ts`

Хранит товары, добавленные в корзину.

**Ответственность:**
- добавить товар в корзину,
- удалить товар,
- очистить корзину,
- посчитать сумму,
- вернуть количество товаров,
- проверить наличие товара в корзине.

**Основные методы:**
- `add(product: IProduct): void`
- `remove(id: string): void`
- `clear(): void`
- `getItems(): IProduct[]`
- `getTotal(): number`
- `getCount(): number`
- `contains(id: string): boolean`

### `BuyerModel`
Файл: `src/components/models/BuyerModels.ts`

Хранит данные покупателя и выполняет валидацию.

**Поля состояния:**
- `payment: PaymentMethod | null`
- `address: string`
- `email: string`
- `phone: string`

**Основные методы:**
- `setField(field, value): void`
- `getData()`
- `validate()`
- `clear(): void`

**Валидация проверяет:**
- выбран ли способ оплаты,
- заполнен ли адрес,
- заполнен ли email и соответствует ли формату,
- заполнен ли телефон и соответствует ли формату.

## Сценарий работы приложения

### 1. Загрузка каталога
1. `main.ts` вызывает `api.getProducts()`.
2. После получения данных вызывается `productsModel.setItems(...)`.
3. Модель эмитит `catalog:changed`.
4. Presenter создаёт карточки `CardCatalog` и передаёт их в `Gallery`.

### 2. Открытие карточки товара
1. Пользователь нажимает на карточку в каталоге.
2. `CardCatalog` эмитит `product:open`.
3. Presenter вызывает `productsModel.setPreview(id)`.
4. Модель эмитит `preview:changed`.
5. Presenter создаёт `CardPreview` и открывает его в `Modal`.

### 3. Работа с корзиной
1. Пользователь нажимает кнопку действия в `CardPreview`.
2. `CardPreview` эмитит `card:action`.
3. Presenter:
   - добавляет товар в корзину, если его там не было,
   - удаляет товар, если он уже был в корзине.
4. После действия модальное окно карточки закрывается.
5. `CartModel` эмитит `basket:changed`.
6. Presenter обновляет счётчик товаров в `Header` и при необходимости содержимое корзины.

### 4. Оформление заказа
1. Пользователь открывает корзину.
2. `BasketView` эмитит `basket:checkout`.
3. Presenter открывает `OrderForm`.
4. При вводе данных формы эмитят `form:changed`.
5. Presenter обновляет `BuyerModel`.
6. `BuyerModel` эмитит `buyer:changed`.
7. Presenter обновляет текущую открытую форму.
8. После сабмита первого шага открывается `ContactsForm`.
9. После сабмита второго шага Presenter вызывает `api.postOrder(...)`.

### 5. Успешное оформление
1. После успешного ответа API открывается `SuccessView`.
2. Затем Presenter очищает:
   - корзину,
   - данные покупателя.
3. При клике на кнопку в success-модалке окно закрывается.

## Роль `main.ts`

`main.ts` выполняет роль Presenter:
- создаёт экземпляры моделей,
- создаёт экземпляры представлений,
- подписывается на события моделей и view,
- связывает действия пользователя с методами моделей,
- координирует открытие и закрытие модальных окон,
- вызывает API,
- инициирует первичную загрузку каталога.

## Особенности реализации

- Все шаблоны компонентов заданы в `index.html`.
- Для клонирования шаблонов используется `cloneTemplate`.
- Для безопасного поиска DOM‑элементов используется `ensureElement`.
- В проекте используется событийная архитектура без прямой связки View ↔ Model.
- Повторное использование кода реализовано через базовые классы `Component`, `Card`, `FormBase`.
- Каталог, корзина и формы обновляются реактивно через события моделей.
- Недоступный товар нельзя купить, но можно открыть в модальном окне и посмотреть описание.
